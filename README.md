# 3DGameStudy_Repository
 3D 게임 유니티 프로젝트 기반 수업
</br></br>

### 1일차
- 캐릭터 에셋 다운로드, 플레이어 움직임 구현, 카메라 시점 (1인칭, 3인칭, 플레이어는 움직이지 않는 3인칭) 구현
- c# 기초적인 구조 학습 (함수, 클래스, 변수선언)
- 레벨디자인1

### 2일차
- 총기 모델 에셋, 사운드, 애니메이션 추가
- 카메라 줌 상태 구현, 블랜트 트리 이용해서 3D상황의 애니메이션 구현, 사운드 약간 구현 (총 발사, 총기 장착)

### 3일차
- 애니메이터 레이어를 이용해서 상체, 하체 애니메이션 구별(Avatar Mask 이용)
- 캐릭터 컨트롤러와 다른 오브젝트 콜라이더가 충돌(트리거)하면 애니메이션, 사운드, 위치 이동 구현
  - 캐릭터 컨트롤러는 물리계산과 충돌 감지 계산을 위해서 자체적으로 위치를 강제 하기 때문에 트랜스폼으로 이동시킬려면 캐릭터 컨트롤러를 비활성화하고 이동시켜야 함.
- 피격 애니메이션, 픽업 애니메이션 구현
- 애니메이션 속도 조절 구현 : (AnimatorStateInfo)를 이용해서 애니메이터 레이어위치(베이스 레이어이거나 1이거나)를 확인하거나 애니메이션의 활성화 상태를 확인 가능함.
- rig 이용, 레이캐스트로 사격 구현
- 레벨디자인2

### 4일차
- LayCast로 LayerMask를 이용해서 충돌 체크
- LayCast 배열로 다수 충돌(관통) 구현, BoxLayCast로 아이템 픽업 상호작용 구현
- 픽업 오디오 추가
- 아이템(라이플)을 먹으면 1번 키가 활설화, 1번 실행 후 에임(조준, 우클릭)가능하게 수정
- 총구 화염 파티클 추가
- 플레이어 1차적으로 마무리
- 좀비 AI 기초 세팅(플레이어 추적, 회전)

### 5일차
- 좀비 애니메이션 추가 (걷고 있을때, 가만히 있을때, 데미지를 입었을때, 죽을때, 공격할때)
- 좀비 상태의 대한 함수 구현, 박스레이캐스트 디버그 출력 구현
- 좀비 사운드 추가
- 코루틴으로 ai 기반 구현 (기본 상태, 추적 상태, 순찰 상태, 공격 상태, 죽음 상태, [도망 상태], {일반 함수: 데미지 받은 상태})
   - ai를 구현할때 함수간의 충돌이나, 로직의 꼬임, 무한 선언 등의 문제를 해결하는 방법 중 하나는 코루틴을 이용해서 start코루틴과 stop코루틴을 이용한다
- 좀비 애니메이션 추가, ai 기본 구조 구현
- ai 자연스럽게 수정1, 하늘 스카이박스, 라이트,활용하여 어둡게 만듦

### 6일차
- 피격 파티클, 폰트 추가, 총알 개수 텍스트ui 추가, 총알 개수 로직 추가, 총알 아이템 추가
- 유니티 에셋 레지스트리의 ai 추가, 플레시 라이트 효과 구현
- 만든것들 프리팹화 (플레이어, 좀비, 캔버스)
- 플레시 줌했을때 다른방향으로 회전되는거 크로스헤어 위치를 비추게 수정, 메뉴화면 기초 세팅 , 캐릭터 체력 텍스트 구현
- 플레이어 죽음 구현, 죽음 애니메이션 추가

### 7일차
- 좀비가 총을 맞으면 1초동안 멈춤 구현
- Nav mesh Link 이용법 학습
- 일시정지 메뉴화면 구현
- 플레이어 코드 싱글톤 형식으로 변경
- 좀비 코드 플레이어 트랜스폼 싱글톤으로 가져오게 변경
- 사운드 메니저 딕셔너리를 구조체를 이용해서 인스펙터에서 확인 할수 있도록 구현
- 사운드 메니저에서 구조체로 가져온 정보들 딕셔너리에 저장하는 함수 추가
- 소리 관련 코드를 사운드메니저를 이용해서 코드 수정
- 백그라운드 음악 추가, 좀비 NavMeshAgent로 인해 죽음처리 되도 따라오는 오류를 NavMeshAgent로컴포넌트 비활성화로 해결
- 플레이어 걷는 소리 추가, 사운드 메니저 bgm 페이드인 페이드 아웃 함수 추가
- 좀비가 죽었을때 죽지않고 애니메이션 구현되는 버그 수정
  - 코틀린의 시간지연(waitforsceonds)을 마구잡이로 사용하면 로직이 꼬이기가 쉬운것 같다.
- 걷는 소리 로직 수정
  - 1.개별적인 코루틴 유지
    - walkSoundCoroutine과 runSoundCoroutine을 따로 관리.
    - if (walkSoundCoroutine == null) 조건을 추가해 중복 실행 방지.
    - 각 코루틴은 moveSpeed 조건을 만족하는 동안 반복 실행됨.
  - 2. 소리 재생을 자동으로 중단
    - moveSpeed가 범위를 벗어나면 while 루프가 멈추고, 코루틴이 종료되면서 walkSoundCoroutine = null이 됨.
    - 다음 프레임에서 다시 WalkSound()가 호출되면 새로운 코루틴이 실행됨.
 - 걷는 사운드 오류 해결, 매쉬링크를 이용해서 좀비 드랍 이벤트 세팅 준비
  - 버티컬 값과, 호라이즌탈 값이 0이 아니면 현재 이동중이라는 비교문으로 현재 이동상태를 체크해서 걷는 사운드 로직을 해결

### 8일차
- 게임 메니저, 파티클 메니저 싱글톤 디자인 형식으로 생성 구현
- 파티클메니저에 오브젝트 풀링 추가
- 파티클 위치 고정 문제 해결, 총 반동과 샷건 총알 탄착군 예시 함수 추가
  - 오브젝트 풀링으로 만든 파티클의 부모를 오브젝트의 위치로 이동 시키면 파티클이 실행되는 동안 위치가 부모 오브젝트를 기준으로 묶여있게됨.
  - 샷건함수와 총 반동 함수는 코트리뷰 필요해보임
- 문 에셋 추가, 문 애니메이션 추가
- 문 상호작용하면 애니메이션 되는 기능 구현, 좀비가 40마리 이상 뭉쳐서 다닐경우 프레임 드랍 해결중
   - 시도한 방법1: 좀비 에셋 프리팹의 몸통 메쉬가 세가지가 활성화 되어있는데 그중에 트라이엥글이 제일 적은 메쉬 이외의 메쉬를 비활성화 시킴
     - 결과: stat에 나오는 배치의 개수와 트라이앵글의 개수는 줄었지만 프레임 드랍 문제는 여전히 있음
   - 시도한 방법2: 맵 전체의 오브젝트들의 static 활성화를 시켰다.
     - 결과: 44마리 정도의 좀비가 모여있어도 프레임드랍이 않생기게 해결되었다.
- +이제는 100마리 즈음의 좀비가 모이면 프레임 드랍이 생기는데 이것도 해결 시도 예정
- 레벨디자인
